# 코디(레이어 착용) 가능성 검토

작성: 2026-10-06

## 결론

**가능하다. 단 "레이어 방식"으로 해야 하고, 남은 위험은 한 가지다 — 실제 상품 사진을 "고정 모델에 맞춰 정렬된 투명 레이어"로 바꾸는 품질.**
이 부분은 실제 사진 10장 정도로 시험해야 판정할 수 있다 (비용 약 $1~5).

| 구성 요소 | 상태 |
|---|---|
| 고정 모델 + 슬롯별 레이어 합성, 상의만 교체 시 하의 유지 | ✅ 동작 확인 (더미 일러스트, 자동 테스트) |
| 보관함 옷만 사용, 원피스·아우터 규칙, 착장 저장, 입은 옷 → 원 판매처 정보 | ✅ 동작 확인 |
| 실제 사진 → 정렬된 레이어 변환 | ⚠️ 미검증 — 외부 AI 필요 |

## 왜 레이어 방식인가

매번 "모델 + 옷 조합" 전체를 AI로 새로 그리는 방식과 비교:

| | 레이어 방식 (채택) | 조합마다 생성 |
|---|---|---|
| 얼굴·체형·자세 | 모델 사진 1장 고정 → **절대 안 바뀜** | 생성할 때마다 미세하게 달라짐 |
| AI 비용 | **상품당 1회** (상의 100 + 하의 100 = 200회, 약 $12) | 조합마다 (100×100 = 10,000회, 약 $600) |
| 옷 바꾸는 속도 | 이미지 겹치기 → 즉시, 오프라인 가능 | 매번 수 초~수십 초 대기 |
| 상의만 교체 | 하의 레이어 그대로 | 전체를 다시 생성 |

## 실제 서비스 파이프라인 (상품 등록 시 1회, 운영자 쪽)

```
상품 사진 ─▶ ① 가상 착용 API: 고정 모델 사진에 이 옷만 입힘
           ─▶ ② 결과에서 옷 영역만 잘라 투명 PNG (원본 모델 사진과의 차이 + 의류 분할)
           ─▶ ③ 레이어 저장 (layerUrl)
앱 ─▶ 모델 사진 위에 하의 → 상의/원피스 → 아우터 순으로 겹쳐 표시 (지금 구현된 화면 그대로)
```

화면 코드는 레이어가 SVG든 PNG든 상관없다. 지금 더미의 `layerUrl`을 실제 PNG로 바꾸면 그대로 동작한다.

## 위험 요소 (시험에서 확인할 것)

1. **잘라내기 품질** — AI가 옷 주변의 팔·피부·그림자를 미세하게 바꾸면 경계가 티 날 수 있다.
2. **따로 만든 레이어끼리의 어울림** — 상의 밑단과 하의 허리선 경계. 상의를 바지에 넣어 입는(tuck) 표현은 어렵다 → 기본은 빼입기로 정한다.
3. **입력 사진 품질** — 판매처 사진이 모델 착용 컷, 바닥에 놓은 컷, 여러 색이 한 장에 있는 컷 등으로 제각각이다. 착용 API가 받는 형태로 정리하는 단계가 필요할 수 있다.
4. **고정 모델 선택** — 머리카락이 어깨를 덮으면 레이어가 머리 위로 올라와 어색하다 → 머리를 묶은 모델, 팔이 몸에서 떨어진 자세.
5. **권리**
   - 모델: 실존 인물 사진은 초상권 문제 → AI로 만든 가상 모델 또는 사용권을 확보한 사진.
   - 상품 사진: 판매처 사진을 가공(착용 합성)해 보여줄 권리 — **법률 확인 필요**.
6. **사이즈** — 모든 옷이 모델 몸에 맞게 입혀진다. 실제 핏·사이즈 차이는 표현되지 않는다.

## 다음 시험 제안 (약 하루, 비용 $5 이하)

- 준비물 (대표님)
  - 실제 상품 사진 10장: 상의 4, 하의 3, 원피스 1, 아우터 2
  - 시험할 API 1곳 가입 (FASHN 또는 Google Vertex). **키는 채팅에 붙이지 말고** 로컬 `.env` 파일에만.
- 작업 (Claude)
  - 고정 모델 사진 준비 방법 제안 (AI 생성 가상 모델)
  - 변환 스크립트: 사진 → 착용 API → 옷 영역 잘라내기 → `layerUrl`
  - 결과를 지금 코디 화면에 그대로 넣어 비교
- 판정 기준
  - 겹쳤을 때 경계가 눈에 띄는가
  - 얼굴·몸이 전혀 변하지 않는가 (레이어 방식이면 구조적으로 보장)
  - 10장 중 몇 장이 손보지 않고 쓸 만한가, 장당 처리 시간·비용

## 추가 검토: Mac mini M4(기본 16GB)로 무료 로컬 운영 (2026-10-06)

| 역할 | 모델 | 라이선스 | 16GB 기본형 |
|---|---|---|---|
| AI 모델 만들기 (1회) | FLUX.1 schnell (Q4, 약 7GB) | Apache-2.0 | 가능, 1장 수십 초~1분대 |
| 옷 입히기 | **FASHN VTON v1.5** (9.7억 파라미터, 2026-01 공개) | **Apache-2.0 (상업 가능)** | 메모리는 충분. 속도·Mac 호환성은 실측 필요 |
| 자연스러운 완성컷 다듬기 | Qwen-Image-Edit (200억 파라미터) | Apache-2.0 | Q4도 13GB + 보조 모델 → 16GB는 부족, 32GB 이상 필요 |

- 실시간은 불가: H100에서 5초짜리 모델이라 Mac mini에서는 장당 수십 초~수 분으로 **추정**(미측정). 사용자가 옷을 누를 때마다 생성하면 안 된다.
- 구조: 상품 등록 시 밤새 배치로 레이어를 만들어 두고, **사용자가 옷을 누르면 미리 만든 레이어를 겹치기만 한다 → 즉시 적용(이미지 교체, 0.1초 이내)**. 클릭 시점에 AI는 돌지 않는다.
- 착장 전체를 한 장으로 다시 그리는 단계는 **필수가 아니다**. 실제 사진 시험에서 레이어 경계가 어색할 때만 "고화질 저장" 같은 선택 기능으로 배경 처리한다(적용 속도와 무관).
- 자연스러움은 클릭 시점이 아니라 등록 시점에 확보한다: 같은 모델·자세·조명으로 생성, 그림자를 포함한 부드러운 잘라내기, 필요하면 상품당 변형 레이어(넣어 입기/빼 입기, 아우터 안에 입은 버전)를 미리 만들어 상황에 맞게 고른다.
- 위험: 오픈소스 착용 코드는 대부분 NVIDIA(CUDA) 기준이라 Mac(MPS)에서 손봐야 할 수 있다. 동시 사용자가 많아지면 대기열이 길어진다.
